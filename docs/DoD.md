# Definition of Done (DoD)

Ce document définit la **Definition of Done (DoD)** du projet. Elle s’applique à **toutes les tâches et Pull Requests**, quel que soit leur type (feature, bug, refactor, documentation).

Une tâche est considérée comme **Done** uniquement si **tous les critères suivants sont respectés**.

## Une tâche est Done quand :

1. **Le code est terminé et fonctionnel**
   - Le code est écrit, lisible et compréhensible
   - Le projet compile et s’exécute sans erreur

2. **Les tests sont validés**
   - Tous les tests existants passent
   - Des tests ont été ajoutés lorsque la tâche le nécessite

3. **Le comportement attendu est vérifié**
   - Le fonctionnement a été vérifié manuellement si besoin
   - L’application EasySave a été exécutée pour valider le résultat

4. **La documentation minimale est à jour**
   - Les noms de classes, méthodes et variables sont explicites
   - Le README et/ou les commentaires ont été mis à jour si nécessaire

5. **La Pull Request est prête**
   - Les fichiers générés (JSON / logs) sont conformes au format attendu, le cas échéant
   - La PR est relue, approuvée et mergée (ou prête à l’être)

Cette Definition of Done (DoD) garantit un **niveau de qualité commun**, une meilleure **maintenabilité** et un **suivi clair de l’avancement** du projet.
